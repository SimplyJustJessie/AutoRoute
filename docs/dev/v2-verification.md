# v2 end-to-end verification runbook (for a local agent)

Audience: a coding agent running **on the real machine** (live PipeWire session, `pactl`,
`pw-dump`, `jq`, `dotnet` 10 available) with the repo checked out on the v2 branch. Everything in
Part A is shell-executable — no GUI interaction needed, because externally editing `rules.json` is
a first-class path (the store hot-reloads it and the watcher reconciles), exercising the same
engine code the UI flyouts call. Part B is a short human checklist for the flyout UI itself.

Report every step as PASS/FAIL with the actual command output. Stop and report (don't improvise a
fix) if a step fails. The gate (`scripts/v2-gate.sh --restart`) already passed 11/11 on this
machine — this runbook verifies the *product*, not the mechanism.

**Safety notes**

- `~/.config/autoroute/rules.json` is the user's REAL routing policy. Only ever edit it with the
  targeted `jq` commands below (add/remove the `TestSink` entry). Never overwrite or truncate it.
  Back it up first (step A0) and restore on any doubt.
- A malformed `rules.json` write is tolerated (last-good kept) but the edit will be silently
  ignored — always write valid JSON via `jq` + `sponge`/temp-file, never `sed` into it.
- Step A4 restarts the audio stack — audio will drop for a couple of seconds. Do it only when
  that's acceptable.
- AutoRoute is single-instance (unix socket). Make sure no other instance is running before
  starting one (`pgrep -af AutoRoute`).

Conventions used below:

```bash
RULES=~/.config/autoroute/rules.json
DROPIN=~/.config/pipewire/pipewire-pulse.conf.d/autoroute-sinks.conf
mods() { pactl list modules short | grep -c "sink_name=TestSink"; }        # expect 0 or 1
node_present() { pw-dump | jq -e '[.[] | select(.info.props["node.name"]=="TestSink")] | length >= 1' >/dev/null; }
```

## Part A — agent-executable

### A0. Build, back up, launch

```bash
cd <repo> && git fetch origin claude/v2-planning-7a5akz && git checkout claude/v2-planning-7a5akz
dotnet build AutoRoute.slnx                        # expect: 0 errors
dotnet test AutoRoute.slnx                         # expect: all pass
cp -a "$RULES" "$RULES.bak-v2-verify" 2>/dev/null || echo "no rules.json yet (fine)"
pgrep -af AutoRoute                                # expect: no running instance; stop it if present
dotnet run --project src/AutoRoute.App -- --background &   # tray-only; keep this shell's job id
sleep 3
```

PASS when: build + tests green, app runs (process alive), and — **legacy import check** — if the
user's static `virtual-sinks.conf` still exists in `~/.config/pipewire/pipewire-pulse.conf.d/`,
`jq '.virtualSinks' "$RULES"` now lists its sinks (GameSink, MusicSink, DiscordSink, DesktopSink)
and the app log (stdout of the job) contains a warning naming that file. If the file was already
removed, `virtualSinks` may be empty — note which case applied.

### A1. Declare a sink externally → it appears everywhere

```bash
jq '.virtualSinks += [{"id":"v2-verify","name":"TestSink","description":"V2 Test Sink","channels":"Stereo"}]' \
   "$RULES" > /tmp/rules.new && mv /tmp/rules.new "$RULES"
sleep 3
node_present && echo NODE-OK                                        # sink node exists
pw-dump | jq -r '.[] | select(.info.props["node.name"]=="TestSink") | .info.props["autoroute.managed"]'  # expect: true
mods                                                                # expect: exactly 1
grep -c "sink_name=TestSink" "$DROPIN"                              # expect: 1 (drop-in synced)
head -2 "$DROPIN"                                                   # expect: the "Generated by AutoRoute" header
```

### A2. Idempotence under churn

```bash
sleep 5; mods                                                       # still exactly 1 (no duplicate loads)
```

### A3. Flagship v1 loop on a v2 sink *(only if an app is currently playing audio)*

Pick any live `Stream/Output/Audio` node (`pw-dump | jq -r '.[] | select(.info.props["media.class"]=="Stream/Output/Audio") | .info.props["application.name"]' | head -1`). Add a rule routing it to TestSink:

```bash
jq --arg app "<APP>" '.rules += [{"id":"v2-verify-rule","name":"verify → TestSink","enabled":true,
  "source":{"predicates":[{"field":"ApplicationName","op":"Equals","value":$app}]},
  "target":{"predicates":[{"field":"NodeName","op":"Equals","value":"TestSink"}]}}]' \
  "$RULES" > /tmp/rules.new && mv /tmp/rules.new "$RULES"
sleep 3
pw-dump | jq '[.[] | select(.type=="PipeWire:Interface:Link") | select(.info.props["autoroute.managed"]=="true" or .info.props["autoroute.managed"]==true)] | length'   # expect: >= 2 (FL+FR)
```

Then quit and relaunch the audio app (new node ids) → the links reappear without touching AutoRoute.
Skip this step (and say so) if no app is playing.

### A4. PipeWire restart with AutoRoute running *(audio interruption)*

```bash
systemctl --user restart pipewire pipewire-pulse wireplumber
sleep 5
node_present && echo NODE-OK
mods                                                                # expect: exactly 1 — the drop-in
                                                                    # and the watcher must NOT double-create
```

### A5. AutoRoute-independence (drop-in alone)

```bash
kill -TERM %1 && sleep 2 && ! pgrep -af AutoRoute                   # graceful stop, no instance left
systemctl --user restart pipewire-pulse
sleep 3
node_present && echo NODE-OK                                        # sink exists WITHOUT AutoRoute running
mods                                                                # expect: 1
```

### A6. Deletion converges everything

```bash
dotnet run --project src/AutoRoute.App -- --background & 
sleep 3
jq 'del(.virtualSinks[] | select(.name=="TestSink")) | del(.rules[] | select(.id=="v2-verify-rule"))' \
   "$RULES" > /tmp/rules.new && mv /tmp/rules.new "$RULES"
sleep 3
mods                                                                # expect: 0 (stale tagged module unloaded)
grep -c "sink_name=TestSink" "$DROPIN" || echo DROPIN-CLEAN         # expect: no entry (or file deleted
                                                                    # entirely if virtualSinks is now empty)
node_present || echo NODE-GONE
```

Note: the module unload here is the SinkReconciler's *stale-cleanup* path (module args carry
`autoroute.managed=true`, name no longer declared) — the same engine code the UI delete uses.

### A7. Cleanup + report

```bash
kill -TERM %1 2>/dev/null
diff <(jq -S . "$RULES.bak-v2-verify") <(jq -S . "$RULES")          # expect: only changes are the
                                                                    # legacy-import additions (if A0
                                                                    # imported) — nothing else
```

Report the PASS/FAIL table for A0–A7 with raw outputs, and note anything unexpected in the app's
stdout (reconcile warnings, backoff messages).

## Part B — human checklist (GUI flyouts; ~3 minutes)

Run `dotnet run --project src/AutoRoute.App` (windowed) and verify:

1. **Create:** "+ New Sink" in the toolbar → flyout. Type an invalid name (`bad name!`) → inline
   validation message, Create disabled. Type `TestSink`, description `V2 Test Sink` → Create. The
   column appears within ~1 s **with a VIRTUAL chip** in its header.
2. **Duplicate guard:** open the flyout again, type `TestSink` → "already declared" message.
3. **Delete impact:** drag any Source onto the TestSink column (creates a rule), then click the
   column's **×** button → the confirm flyout lists that rule with an "Also delete these
   rules/suppressions" checkbox, default **checked**. Confirm → column disappears, and
   `jq '.rules, .virtualSinks' ~/.config/autoroute/rules.json` shows both gone (one save).
4. **Banner:** if the legacy `virtual-sinks.conf` is restored temporarily, relaunching shows the
   amber banner naming the file; removing the file and relaunching clears it.
5. **Unmanaged columns** (hardware sink, Discord's recStream): **no** VIRTUAL chip, **no** ×
   button.
